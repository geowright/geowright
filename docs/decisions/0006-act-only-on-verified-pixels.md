# 0006. Act only on verified pixels

- Status: Superseded by 0019
- Date: 2026-09-20
- Decided by: Shai Sinai

## Decision
A click candidate is generated by simple geometry and always verified by the map library's own
hit test before real input is sent. An action fires only when the target resolves to exactly one
feature, is still, is actually on the feature, is the topmost visible hit, and is uncovered by any
DOM element. On a globe, a location counts as reachable only if `unproject(project(location))`
round-trips back to itself.

## Why
Candidate generation only needs to be close enough for the hit test to confirm it, so the geometry
code stays simple and a wrong estimate costs a retry, never a wrong click. Before the round-trip
check existed, a click at a location on the far side of a globe silently hit whatever was drawn on
the near side instead, with no error — the worst kind of bug, because `project()` answers for the
far side too. This rules out acting on a computed pixel without verification, and rules out
treating a feature's own on-top label as something that blocks a click.

## Consequences
- easy: geometry bugs turn into a retry or a clear diagnostic, never a silent wrong click; works unchanged on rotated, pitched, globe and terrain maps
- costs: candidate search is capped, so a badly occluded shape reports "occluded" rather than searching forever
- enforced by: the actionability checks in `src/inpage/engine.ts`; a mutation test that disables click-time verification and confirms a targeted race spec then fails
