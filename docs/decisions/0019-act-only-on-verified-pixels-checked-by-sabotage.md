# 0019. Act only on verified pixels; the click-time check is held by sabotage specs

- Status: Accepted
- Date: 2026-09-24
- Decided by: Shai Sinai
- Supersedes: 0006

## Decision
0006's decision, unchanged: a click candidate is generated by simple geometry and always verified by the
map library's own hit test before real input is sent, and again when the real event arrives. An action
fires only on the one target, still, on the feature, topmost, not under DOM; on a globe a location counts
only if it round-trips.

## Why
0006 named "a mutation test that disables click-time verification" as its enforcement. No such test
exists as a standing check. What holds the rule is a set of sabotage specs: the app changes the map
between the aim and the press, and the spec fails if the press is accepted. Removing the click-time
checks by hand makes them fail (shown in the audit fixes of 2026-09-24).

## Consequences
- easy: a regression in click-time verification fails a named spec, not a mutation run someone must remember
- costs: each rejection path needs its own sabotage spec; a path without one is unguarded
- enforced by: the actionability checks in `src/inpage/engine.ts`; the click-time sabotage specs in `tests/act.spec.ts` (a pan between aim and press, a look-alike sliding under the pointer, a fill or a DOM element appearing over the target), `tests/moving.spec.ts` and `tests/touch-keyboard.spec.ts` (a rejected tap delivers nothing)
